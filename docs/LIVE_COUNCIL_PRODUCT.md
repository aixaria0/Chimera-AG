# Chimera v0.11 — Live Council and jcode in the local web product

The existing Chimera browser application now exposes **three connected workflows**:

1. **Single model** — real Ollama /api/chat, unchanged from v0.10.
2. **Live council** — the existing `chimera.council.Council` runs two specialist workers, a synthesizer, and a verifier against actual installed Ollama models. Every response is generated by live inference. The API returns per-agent model IDs, generated-token counts, model agreement, latency and total attempted calls.
3. **jcode coding** — only when an operator **explicitly enables it on their own local machine**, the browser calls the existing `execute_workflow` from `chimera.coding_workflow`: Agency Agents planner → jcode implementer → Agency Agents reviewer → a fixed local test suite. It requires a clean, separate Git working tree, does not commit or deploy, and returns the phase results for manual review.

Nothing in the UI claims different prompts sent to the **same model weights** are independent verification. One installed model is enough to use the live council, but that case is a multi-role deliberation, not a diverse model ensemble. For diverse local model inference, pull additional Ollama models and enter up to four exact installed model names in the Council panel, one per line; role order is worker, worker, synthesizer, verifier. With fewer models, weights may be shared across roles. A verifier agreeing with other models is not proof of factual correctness.

## Real local council (Docker, no jcode required)

```bash
git clone https://github.com/aixaria0/Chimera-AG.git
cd Chimera-AG
docker compose up -d --build
```

The default model `qwen2.5:1.5b` downloads automatically. Open http://127.0.0.1:8080, select **Agent council**, and ask a question. When a call fails, the app reports the failure rather than returning a simulated completion. The existing `scripts/real_model_smoke.py` now verifies **four actual generation calls** using the real `smollm2:135m` CPU model in GitHub Actions; it also ensures code execution is disabled in the standard Docker deployment.

To load the **actual upstream Agency Agents specialist prompts into the Docker council**, clone the trusted role repository locally and start with the optional read-only mount:

```bash
git clone https://github.com/msitarzewski/agency-agents.git ../agency-agents
CHIMERA_AGENCY_PATH="$(cd ../agency-agents && pwd)" \\
  docker compose -f compose.yaml -f compose.agency.yaml up -d --build
```

The browser will report that Agency Agents roles are active. This read-only mount does not install or enable jcode inside Docker and does not grant repository write access.

To use more than one set of weights, first pull locally, for example:

```bash
docker compose exec -T ollama ollama pull qwen2.5:3b
docker compose exec -T ollama ollama pull llama3.2:1b
```

Then enter the exact installed model names in the Council panel. Ollama availability, CPU/GPU memory, throughput and inference time still constrain the number of simultaneous calls. The Compose default sets one Ollama parallel generation at a time, so requests may queue.

## Real Agency Agents + jcode coding workflow on your machine

This mode cannot be silently enabled by visiting the webpage. The standard Docker image **does not install jcode, mount your source tree, or expose local code execution**. Run Chimera from a host where actual jcode, Ollama, and the Agency Agents checkout are configured. Use a trusted, clean disposable Git worktree containing your selected project's fixed tests.

```bash
git clone https://github.com/msitarzewski/agency-agents.git /path/to/agency-agents
git clone https://github.com/aixaria0/Chimera-AG.git /path/to/Chimera-AG
cd /path/to/Chimera-AG
python -m pip install -e '.[test]'

# Install/configure the REAL jcode runtime using its upstream instructions:
# https://github.com/1jehuang/jcode
# Start local Ollama and pull a suitable real model:
ollama pull qwen2.5:1.5b

# The task workspace must be a SEPARATE clean Git worktree you authorize.
CHIMERA_ENABLE_CODE=1 \
CHIMERA_AGENCY_CHECKOUT=/path/to/agency-agents \
CHIMERA_CODE_WORKSPACE=/path/to/clean-git-task-worktree \
CHIMERA_HOST=127.0.0.1 \
OLLAMA_HOST=http://127.0.0.1:11434 \
python -m chimera.product
```

Open http://127.0.0.1:8080, select **jcode coding**, read the explicit execution warning, tick the authorization box, and send a bounded task. The server accepts coding calls only when the operator enabled this mode, binds to loopback, and receives an explicit same-origin browser request. The browser cannot select filesystem paths, shell commands, arbitrary test commands or jcode binaries. Run it only in an independently isolated development workspace with jcode permissions you have reviewed. No GitHub credentials or old exposed API tokens are required by Chimera; jcode itself may require fresh private provider configuration.

**Manual review is mandatory:** the coding workflow's successful process exit does not mean the review found no problems. Inspect each generated change and the review text, rerun your tests, then decide whether to commit or open a PR. The web app never commits, pushes, or deploys on your behalf.

## Architecture and honest validation

`chimera/product.py` -> `chimera/product_integrations.py` -> `chimera/council.Council` -> real `OllamaBackend.chat` -> Ollama weights.

For local code: `chimera/product.py` -> `chimera/product_integrations.run_live_coding` -> `chimera/coding_workflow.execute_workflow` -> role files from the real Agency Agents checkout -> installed jcode binary -> operator-selected clean worktree -> fixed test suite.

The GitHub-hosted CPU workflow proves the actual **model council inference** path using real weights, not a scripted answer. It does **not** assert that a live jcode installation was operated in CI, that four different models were used, or that the council outperforms a single-model answer. GitHub's ephemeral test runner is not your persistent production server.
